---
title: "Authenticating requests to the KrateCMS API"
description: "How to obtain a Bearer token from the KrateCMS admin, use it on write requests, and understand tenant scoping and token revocation."
---

KrateCMS uses Laravel Sanctum personal access tokens for API authentication. Post and release-note read endpoints (`GET`) are public and work without any credentials. Write endpoints (`POST`, `PATCH`, `DELETE`) — and *every* [media](/api/media) endpoint, reads included — require you to pass a valid Bearer token with every request.

The same token authenticates the [MCP server](/integrations/mcp).

## Obtain a token

### Admin UI (recommended)

Tokens are issued from the platform's central admin at `/admin/tokens`, which requires super-admin access. That page can:

- Issue new tokens with a descriptive label and a chosen expiry — 7, 30, or 90 days, or no expiry at all
- List all active tokens with their last-used timestamps
- Revoke individual tokens

<Note>
  **Token management isn't available from your own site's admin.** If you need a token for your site, ask your platform administrator to issue one for your user account. Every issuance and revocation is recorded in an audit log.
</Note>

When a token is created, the plaintext value is displayed **once** in a confirmation banner. Copy it immediately — KrateCMS stores only a hashed version and cannot show it again.

## Token expiry

Each token carries its own expiry, chosen when it's issued. A token issued with no expiry stays valid until it's revoked — useful for a long-running integration you don't want to re-key on a schedule.

<Note>
  An expired token is rejected like an invalid one. If a working integration starts failing authentication without any change on your side, check whether its token has passed its expiry date.
</Note>

## Use the token

Pass the token as a Bearer credential in the `Authorization` header on every write request.

```http
Authorization: Bearer <your-token>
Accept: application/json
```

<CodeGroup>

```bash curl — create a post
curl -X POST https://acme.yoursite.com/api/v1/posts \
  -H "Authorization: Bearer <your-token>" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"title":"My New Post","content":"<p>Hello world</p>","status":"draft"}'
```

</CodeGroup>

<Warning>
Tokens grant full write access to your tenant's content. Treat them like passwords. Never expose a token in client-side JavaScript, commit it to source control, or include it in public URLs.
</Warning>

## Tenant scoping

A token belongs to a user, and that user belongs to one context. A token for a user on `acme.yoursite.com` **cannot** be used against `beta.yoursite.com` — attempting it returns `403` immediately.

The host you call also decides what the token acts on: the same request sent to your site's domain operates on your site's content, and sent to the central platform domain it operates on platform content. If you need API access across multiple sites, request a separate token for a user in each one.

## Error responses

```json
// 401 — no token supplied, or the token is invalid
{ "message": "Unauthenticated." }
```

```json
// 403 — token is valid but used against the wrong tenant
{ "message": "This action is unauthorized." }
```

## Revoke a token

Revocation happens on the same central admin page that issues tokens, so ask your platform administrator to revoke it — from `/admin/tokens` they click **Revoke** on the token row. The action is recorded in the audit log with the actor's identity and timestamp.

Revocation takes effect immediately — there is no grace period.
