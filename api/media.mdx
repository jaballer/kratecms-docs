---
title: "Media API: list, search, and update library assets"
description: "Reference for the KrateCMS media endpoints: list and filter your media library, fetch a single asset, and edit alt text and titles."
---

The Media API exposes your [media library](/content/media-library) — listing and searching assets, and editing their alt text and titles. All paths are prefixed with `/api/v1` and are scoped to the tenant domain you send the request to.

<Warning>
  **Media has no public tier.** Unlike posts and release notes, *every* media endpoint — reads included — requires a Bearer token whose user holds the **Media** permission (editor and above). There is no guest access to the library at any level.
</Warning>

<Note>
  You can't upload file bytes over the API. Uploading happens through the admin; these endpoints read and describe assets that already exist. To attach an existing asset to a post, use [`POST /api/v1/posts/{id}/featured-image`](/api/posts#post-/api/v1/posts/id/featured-image) or [`POST /api/v1/posts/{id}/audio`](/api/posts#post-/api/v1/posts/id/audio).
</Note>

---

## GET /api/v1/media

Returns a paginated list of media assets in the current tenant context.

<ParamField query="search" type="string">
  Free-text search across the asset's filename, alt text, and title.
</ParamField>

<ParamField query="type" type="string">
  Filter by kind. One of `image`, `video`, `audio`, or `document`.
</ParamField>

<ParamField query="source" type="string">
  Filter by where the asset came from. One of `upload`, `ai`, or `import`.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of assets per page. Defaults to `15`; maximum `100`.
</ParamField>

<ParamField query="page" type="integer">
  Page number to retrieve. Defaults to `1`.
</ParamField>

<Note>
  Trashed assets are never returned, and there's no API surface for trashing, restoring, or deleting. Those actions live in the admin only.
</Note>

<Note>
  Pagination links keep your filters. `first`, `last`, `prev`, and `next` carry the `search`, `type`, and `source` you sent, so following `next` gives you page two of the *same* filtered set.
</Note>

### Example

<CodeGroup>

```bash curl
curl "https://acme.yoursite.com/api/v1/media?type=image&source=ai" \
  -H "Authorization: Bearer <your-token>" \
  -H "Accept: application/json"
```

</CodeGroup>

## GET /api/v1/media/\{id\}

Returns a single media asset by id.

<ParamField path="id" type="integer" required>
  Numeric ID of the asset. Media has no slug — this segment is always numeric.
</ParamField>

Returns `404` if no asset with that id exists in the current tenant context.

### Response fields

<ResponseField name="data.id" type="integer">
  Unique numeric identifier for the asset.
</ResponseField>

<ResponseField name="data.url" type="string">
  Absolute URL to the stored file.
</ResponseField>

<ResponseField name="data.mime" type="string | null">
  The file's MIME type, for example `image/jpeg` or `audio/mpeg`. May be `null` for assets registered before their type could be read.
</ResponseField>

<ResponseField name="data.size" type="integer | null">
  File size in bytes, or `null` if it couldn't be measured.
</ResponseField>

<ResponseField name="data.width" type="integer | null">
  Pixel width. Always `null` for non-image assets.
</ResponseField>

<ResponseField name="data.height" type="integer | null">
  Pixel height. Always `null` for non-image assets.
</ResponseField>

<ResponseField name="data.alt" type="string | null">
  Alt text describing the asset. This is the single source of the description wherever the asset is used as a featured or page-block image.
</ResponseField>

<ResponseField name="data.title" type="string | null">
  The asset's library caption. Seeded from the uploaded filename, and editable.
</ResponseField>

<ResponseField name="data.source" type="string">
  Where the asset came from: `upload`, `ai`, or `import`.
</ResponseField>

## PATCH /api/v1/media/\{id\}

Updates an asset's alt text and title. These are the only editable fields — the file itself is immutable.

<ParamField path="id" type="integer" required>
  Numeric ID of the asset to update.
</ParamField>

<ParamField body="alt" type="string">
  New alt text, up to 255 characters. Send an empty string to clear it.
</ParamField>

<ParamField body="title" type="string">
  New library title, up to 255 characters. Send an empty string to clear it.
</ParamField>

Returns `200 OK` with the updated asset.

### Example

<CodeGroup>

```bash curl
curl -X PATCH https://acme.yoursite.com/api/v1/media/118 \
  -H "Authorization: Bearer <your-token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"alt": "Keynote speaker on stage at the 2026 conference"}'
```

</CodeGroup>

<Warning>
  **Editing `alt` changes every featured-image and page-block placement.** For those, alt text is stored on the asset rather than on the post or page using it, so a single `PATCH` updates them all at once. That's what makes it worth fixing centrally — and worth checking before you script a bulk update.

  Inline images inside post content are the exception: they carry their own per-placement alt text, which this endpoint does not touch.
</Warning>

<Note>
  Omit a field to leave it untouched. Sending it blank — empty or whitespace-only — clears it. That's the opposite of what happens at upload time, where a blank title falls back to the filename; here you're erasing something that already exists.

  Whitespace is treated as blank deliberately: a space-only alt would satisfy "has alt text" checks everywhere the asset is used while telling a screen reader nothing.
</Note>
