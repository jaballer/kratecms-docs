title: "KrateCMS REST API: base URL, auth, and error codes"
description: "A reference overview of the KrateCMS REST API: base URL, tenant scoping, authentication requirements, pagination, rate limits, and error codes."
---

The KrateCMS REST API gives you programmatic access to your CMS content over HTTPS. All requests and responses use JSON. The API is versioned — every endpoint lives under `/api/v1` — so future breaking changes will land on a new version without affecting your existing integrations.

An [OpenAPI 3.1 specification](https://github.com/jaballer/kratecms/blob/main/docs/api/openapi.yaml) is available in the repository, covering every endpoint with request/response schemas, authentication details, and error shapes.

## Resources

| Resource | Public reads? | Endpoints |
|---|---|---|
| [Posts](/api/posts) | Yes | List, get by id or slug, create, update, delete, attach a featured image, attach audio |
| [Release notes](/api/release-notes) | Yes | List, get — plus create, update, delete **from the central platform domain only** |
| [Media](/api/media) | **No** | List, get, update |

<Note>
  Media is the exception to the public-read rule: every media request — including reads — requires a token whose user holds the **Media** permission. Posts and release notes serve published content to anyone.
</Note>

## Base URL

Every endpoint is relative to your tenant's domain:

```
https://acme.yoursite.com/api/v1
```

The API is tenant-scoped. A request to `acme.yoursite.com/api/v1/posts` returns only that tenant's posts. Records from other tenants are never visible, regardless of the token you supply.

<Note>
  **One exception: writing release notes.** Release notes are platform-wide announcements shared by every site, so `POST`, `PATCH`, and `DELETE` on `/release-notes` work only against the **central platform domain** and are rejected on a site domain. Reading them works from anywhere. See [Release Notes API](/api/release-notes#writing-release-notes).
</Note>

## Authentication

For posts and release notes, read endpoints (`GET`) are public and require no credentials, while write endpoints (`POST`, `PATCH`, `DELETE`) require a Bearer token in the `Authorization` header. Every media endpoint requires a token, reads included. See [Authenticate with the KrateCMS API](/api/authentication) for how to obtain and use tokens.

<Note>
  Public reads are resolved as a guest, even when you send a token. Drafts and members-only posts aren't returned by the public list endpoint on that basis alone — see the notes on each endpoint for how authenticated access differs.
</Note>

## Cross-origin requests (CORS)

The API sends CORS headers, so a browser-based single-page app can call it directly from another origin. Out of the box, requests are allowed from your site's own origin and from the common local dev servers `http://localhost:5173` (Vite) and `http://localhost:3000`. The `X-RateLimit-Limit` and `X-RateLimit-Remaining` headers are exposed to the browser.

To call the API from any other origin — your production front-end domain, for example — ask your platform operator to add it to the allowed origins (`CORS_ALLOWED_ORIGINS`). Because the API permits credentialed requests, each origin must be listed explicitly; a wildcard `*` is not used.

## Rate limiting

All API routes run under the `throttle:api` middleware: **60 requests per minute per token or IP**. When you exceed the limit, the API responds with `429 Too Many Requests` and a `Retry-After` header telling you how many seconds to wait before retrying.

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 30
```

## Pagination

List endpoints return a paginated envelope. Results are in the `data` array; pagination state is in `meta` and cursor links are in `links`.

<CodeGroup>

```bash curl
curl https://acme.yoursite.com/api/v1/posts \
  -H "Accept: application/json"
```

</CodeGroup>

```json
{
  "data": [...],
  "meta": {
    "current_page": 1,
    "last_page": 3,
    "per_page": 15,
    "total": 42
  },
  "links": {
    "first": "https://acme.yoursite.com/api/v1/posts?page=1",
    "last": "https://acme.yoursite.com/api/v1/posts?page=3",
    "prev": null,
    "next": "https://acme.yoursite.com/api/v1/posts?page=2"
  }
}
```

Use the `next` link directly to fetch the following page, or pass a `page` query parameter manually.

## Error responses

All error responses return a JSON body. Validation errors include a per-field `errors` object.

| Status | Meaning |
|--------|---------|
| `401` | Unauthenticated — token missing or invalid |
| `403` | Forbidden — token lacks permission or was issued for a different tenant |
| `404` | Not found |
| `422` | Validation error — inspect the `errors` field for per-field messages |
| `429` | Rate limit exceeded — wait `Retry-After` seconds before retrying |

```json
{
  "message": "The given data was invalid.",
  "errors": {
    "title": ["A post title is required."]
  }
}
```
